🏭 How to Create an ADF Pipeline

Step-by-step guide to build your SAP to Data Lake pipeline

1

Click "+ New Pipeline"

Start by creating a new pipeline from the Pipelines tab

📍 Where to Find It:

  1. Open Azure Data Factory Studio
  2. Click "Author" tab (pencil icon) on the left sidebar
  3. Click "Pipelines" in the Factory Resources panel
  4. Click the "+ New Pipeline" green button
🖱️ Click "+ New Pipeline" Button

This button is at the top of your Pipelines section (as shown in your screenshot)

✅ What Happens:

A blank pipeline canvas opens where you can drag and drop activities to design your data workflow.

2

Add Copy Data Activity

Drag the Copy Data activity to your pipeline canvas

🎯 How to Add Copy Activity:

  1. Look at the Activities panel on the left side of the canvas
  2. Expand "Move & transform" section
  3. Find "Copy data" activity
  4. Drag and drop it onto the canvas
  5. Rename it to something meaningful (e.g., "Copy_SAP_KNA1")

3

Configure Source (SAP)

Tell ADF where to get the data from

📂 Source Configuration Steps:

  1. Click on the Copy Data activity you just added
  2. At the bottom, click the "Source" tab
  3. Click "+ New" next to "Source dataset"
  4. Search for and select "SAP Table"
  5. Select your SAP Linked Service (e.g., "SAP_S4HANA_Production")
  6. Enter the table name (e.g., "KNA1")
  7. Click "OK"

Source Dataset Configuration:

Required because SAP is on-premise
⚠️ Important: Make sure your Self-Hosted Integration Runtime is running! Without it, ADF cannot connect to SAP.
4

Configure Sink (Data Lake)

Tell ADF where to write the data

📍 Sink Configuration Steps:

  1. Still on the Copy Data activity, click the "Sink" tab
  2. Click "+ New" next to "Sink dataset"
  3. Search for and select "Azure Data Lake Storage Gen2"
  4. Choose format: "Parquet" (recommended for big data)
  5. Select your Data Lake Linked Service (e.g., "DataLake_Gen2")
  6. Browse and select container: "bronze"
  7. Enter folder path: "sap/kna1/"
  8. Click "OK"

Sink Dataset Configuration:

Example: KNA1_20260214_020000.parquet

5

Add Parameters (Optional but Recommended)

Make your pipeline flexible with parameters

🔧 Why Use Parameters?

Parameters let you reuse the same pipeline for different tables without creating multiple pipelines.


How to Add Parameters:

  1. Click on empty area of canvas (to select the pipeline itself)
  2. Click "Parameters" tab at the bottom
  3. Click "+ New"
  4. Add parameter name: "TableName"
  5. Type: String
  6. Default value: "KNA1"

Example Parameters:

Parameter Name Type Default Value Purpose
TableName String KNA1 SAP table to extract
TargetFolder String sap/kna1/ Data Lake folder path
FilterCondition String LAND1 = 'AE' Optional WHERE clause
✅ Using Parameters in Your Dataset:

In your source dataset, instead of hardcoding "KNA1", use:

@pipeline().parameters.TableName

Now you can run the same pipeline for KNA1, VBAK, MARA, etc. by just changing the parameter!

6

Test & Debug Your Pipeline

Run your pipeline to make sure it works

🧪 How to Test:

  1. Click "Debug" button at the top of the pipeline canvas
  2. If you have parameters, enter test values in the popup
  3. Click "OK" to start the debug run
  4. Watch the "Output" tab at the bottom to see progress
  5. Wait for the activity to show a ✅ green checkmark (success) or ❌ red X (failed)

Debug Output:

✅ Success! What to Check:
  • ✓ Activity shows green checkmark
  • ✓ Row count looks correct
  • ✓ File appeared in Data Lake (check Storage Explorer)
  • ✓ No error messages in output
❌ If It Failed:
  • Click the ❌ red X to see error details
  • Common issues: IR not running, wrong credentials, table doesn't exist
  • Check "Details" link for full error message
7

Publish Your Pipeline

Save your pipeline to the ADF service

📤 Publishing Steps:

  1. Click "Validate" button to check for errors
  2. Fix any validation errors if they appear
  3. Click "Publish All" button at the top
  4. Review the changes in the popup
  5. Click "Publish" to confirm
⚠️ Important Notes:
  • Debug runs don't require publishing - they run your draft
  • Triggers require publishing - scheduled runs only work on published pipelines
  • Publishing is like "saving to production" - it makes your pipeline available for real use
📤

Publishing...

This saves your pipeline to Azure Data Factory

✅ Pipeline Published Successfully!

Your pipeline is now saved and ready to be triggered manually or on a schedule.

8

Add Trigger / Schedule

Make your pipeline run automatically

⏰ Create a Schedule Trigger:

  1. Click "Add trigger" button at the top of pipeline canvas
  2. Select "New/Edit"
  3. Click "+ New" in the popup
  4. Name your trigger: "Daily-SAP-Extract-2AM"
  5. Type: Select "Schedule"
  6. Start date: Choose today or tomorrow
  7. Recurrence: Select "Daily"
  8. Time: Set to "02:00 AM"
  9. Time zone: "(UTC+04:00) Abu Dhabi"
  10. Click "OK"
  11. Click "Publish All" to activate

Trigger Configuration:

✅ Trigger Created!

Your pipeline will now run automatically every day at 2:00 AM (UAE time).

Next Run: Tomorrow at 02:00 AM

💡 Best Practice: Schedule SAP extracts during off-peak hours (like 2 AM) to minimize impact on SAP system performance.
